# Plan: "Talking head + b-roll + motion" mode (Kitti parity and beyond)

Status: **agreed direction, not started** — owner decisions 2026-10-02. This file is the
source of truth for the plan; update it as decisions change.

## Why
Competitor **Kitti** (kittiapp.com) turns a raw talking-head clip plus a folder of b-roll into a
polished 9:16 promo: tight cuts, kinetic captions, b-roll inserts, the speaker cut out over
b-roll, motion graphics, infographics, transitions, SFX and music. Analysis of three of their
videos: `scratchpad/kitti/` (session-local) — summary below. The owner wants **every technique
they have**, and more.

### How Kitti works (observed)
- Desktop app (Mac/Windows) that drives the user's own **Claude Code / Codex** subscription;
  the coding agent writes a custom renderer per video (one run took "Worked for 16m 9s").
  Local Whisper (GGML/Metal) transcription. Price ฿4,900 one-time; AI cost paid by the user to
  the AI vendor. Their wiki tells users to enable Claude Code "bypass permissions" / Codex
  "full access".
- Workflow: drop a footage folder + brief (+ fonts, sounds) → AI proposes 2–3 concepts / hooks
  → storyboard table (time | picture/edit | spoken line | super text + sound) → local
  "Kitti · Storyboard player" page (~38 shots; per shot: VO, SUPER TEXT spec, effects such as
  fast zoom / push-in / keyframe slide, SFX such as whoosh / pop, source file + range, a notes
  box; "copy all notes" back into the chat) → render → MP4 or CapCut project.
- Techniques seen in the result clip (3:47 raw → 1:21): silence/flub removal; big Thai captions
  with per-word pop and keyword emphasis (yellow); full-screen b-roll; the speaker cut out
  (person matte) over a website / inside a phone mockup; "result" frame with blurred background
  and a "3:47 → 1:21" chip; motion-graphic cards (feature chips popping in, price ticket counting
  up with struck-through old price, discount-code typing + "-5%" badge, sticker labels, mascot
  pop-ins, logo + CTA end card); transitions (glass crack, white flash, slide, blur); zoom
  punches; SFX hits + music bed with ducking; loudness about −14 LUFS.

## Owner decisions (2026-10-02)
- Token cost is **not** a reason to cut a feature — users pay through quota.
- **No CapCut export** in this mode.
- **No AI-generated photoreal images or video** (no Veo/Midjourney-style pixels): risk of fake
  product imagery for affiliate sellers and TikTok's AI-content labelling.
- Graphics ARE generated by AI **as code** (HTML/CSS/JS/SVG) and rendered to video — this is how
  infographics and motion graphics are made. Frequently used pieces also exist as tested
  templates (fast path); anything else the AI writes.
- Missing visuals may be filled from **free stock libraries with commercial-use APIs**
  (Pexels, Pixabay, Unsplash — re-check their current terms before building). Never Google
  Images / arbitrary web images; never scrape TikTok Shop or seller pages (repo hard rule 2);
  product images come from the user.
- Infographic numbers must come from the speech or the user's brief — the AI never invents data.
- The before/after comparison layout in Kitti's ad is marketing, not a feature to copy.

## Mode flow
1. **Ingest**: A-roll (talking head, one or more), b-roll folder (video, photos, screen
   recordings), optional brand kit (logo, colours, fonts, mascot), optional brief.
2. **Understand**: word-level transcription (existing ElevenLabs path); AI tags every b-roll file
   (what it shows, usable ranges, which lines it fits).
3. **Clean the A-roll**: remove silences, flubs, retakes, fillers (extend the silence-cut mode +
   AI retake detection on the transcript).
4. **Concepts**: AI proposes 2–3 concepts (hook, structure, tone); the user picks one.
5. **Storyboard** (per shot): A-roll range + spoken line; layout; visual source (user b-roll /
   stock / generated graphic / text card); caption text + emphasised words + style; motion
   graphic or infographic spec; camera move; transition into next shot; SFX; music cues;
   emotion tag (drives effects, e.g. screen crack on disappointment).
6. **Review**: storyboard player with preview, per-shot notes, "AI revise these shots", approve.
7. **Render** through the compositor below.

### Visual fill priority when a line has no matching user b-roll
1. User b-roll → 2. Infographic (numbers, lists, steps, comparisons, prices) → 3. Stock photo/video
from free libraries (atmosphere / concept) → 4. Animated text card.

## Technical flow — a multi-agent pipeline (owner, 2026-10-02)
This mode is many model calls by design, each a role with its own prompt and JSON schema. (The
"one Gemini call" rule of 2026-10-01 is about the ตัดฉากเด่น cut plan only.) Every stage is an arq
job, persists its output in the project, is billed per call through the existing quota model,
and is resumable (paused_quota resumes at the next stage / next shot). Fan-out stages run per
file / per shot in parallel. All calls go through `packages/llm` (provider-agnostic).

| # | Agent (role) | Input → output | Model kind |
|---|---|---|---|
| 0 | Ingest (no AI) | files → proxies, audio WAV, thumbnails, durations | — |
| 1 | Transcriber | A-roll audio → word-timed transcript | existing STT (ElevenLabs) |
| 2 | B-roll analyst (per file, parallel) | b-roll video/photo → tags, usable ranges, what it shows | video/vision model |
| 3 | A-roll cleaner | transcript (+ audio cues) → keep-ranges without silences, flubs, retakes, fillers | text model |
| 4 | Concept writer | cleaned transcript + brief + b-roll index → 2–3 concepts (hook, structure, tone) | strongest text model |
| 5 | Storyboard director | chosen concept + transcript + b-roll index + brand kit → `storyboard.json` (shots[] with id, A-roll range, line, layout, visual source, caption + emphasis, graphic spec, camera move, transition, SFX, emotion) | strongest multimodal model |
| 6 | Stock researcher (per shot needing stock, parallel) | shot spec → English queries → stock API search → vision pick → downloaded asset + attribution | text + vision |
| 7 | Graphic designer (per graphic shot, parallel) | graphic spec + brand kit + timing → template params, or AI-written HTML/CSS/JS/SVG | strongest coding model |
| 8 | Graphic QA (loop, max N) | sample frames rendered from #7 → checks overflow, overlap, Thai rendering, timing → fixes | vision model |
| 9 | Sound designer | storyboard + music library + beat grid → SFX cues, music pick, duck points | text model + existing beat analysis |
| 10 | Reviser | user's per-shot notes → updates only those shots, re-runs 6–9 for them | strongest model |
| 11 | Renderer (no AI) | storyboard + assets + graphics → MP4 | compositor + code-graphics renderer |

Artifacts per project: `transcript.json`, `broll_index.json`, `concepts.json`, `storyboard.json`,
`graphics/<shot_id>/` (code + rendered transparent clip or frames), `stock/` (+ attribution
manifest), `audio_plan.json`, final render.

Graphics rendering: AI code runs sandboxed in Chromium with a controlled clock, stepped frame by
frame, captured as transparent video/frames; desktop renders locally (Electron offscreen), web
renders on a server-side headless Chromium service; the compositor layers them over the footage.

## Building blocks
| # | Component | Notes |
|---|---|---|
| 1 | **Compositor** shared by web and desktop | layers, keyframes + easing, masks, blur, shadows; desktop = Electron (Chromium), web = WebCodecs engine. Heaviest piece; everything builds on it. |
| 2 | **Code-graphics renderer** | Runs AI-written HTML/CSS/JS/SVG in a sandbox (no network, isolated), steps a controlled clock frame by frame, captures frames. Desktop: Electron offscreen. Web: a browser cannot capture DOM to video reliably → server-side headless Chromium render service (or Canvas-only graphics). AI renders a sample frame and checks overflow/overlap before use. |
| 3 | **Kinetic captions** | per-word timing, emphasis, multiple styles, correct Thai line breaking, brand fonts. |
| 4 | **Template library** | title/question card, feature chips, price ticket count-up, discount code + badge, sticker, mascot pop, result frame + time chip, end card + CTA; affiliate extras: "กดตะกร้า", before/after price, star rating. Infographics: bar/pie, counter, comparison table, steps, checklist, timeline, price tag. |
| 5 | **Person segmentation** | in-browser model (e.g. MediaPipe), computed once and cached; enables speaker-over-b-roll and phone-mockup layouts. |
| 6 | **Layouts** | full A-roll, full b-roll, speaker cut-out over b-roll, split screen, phone mockup, file/photo grid, framed result + blurred bg. |
| 7 | **Effects & transitions** | flash, glass crack, glitch, shake, slide, blur, whoosh, zoom punch (zoom/pan exist), black-and-white for "problem" beats; chosen by emotion of the line. |
| 8 | **Audio** | licensed SFX + music library (not scraped from Pixabay), auto-ducking, loudness normalisation, beat-synced cuts (exists). |
| 9 | **B-roll understanding** | per-file tags + best ranges. |
| 10 | **Stock search** | AI writes English queries, searches the libraries, picks results, stores source + author for attribution/takedowns; "swap image" in the storyboard. Thai-context imagery is thin in these libraries. |
| 11 | **Brand kit** | stored per user, applied to captions and graphics. |
| 12 | **Billing** | estimate + charge every new AI step (concepts, storyboard, b-roll tagging, code graphics) through the existing quota model. |

Reused as-is: transcription, silence cut, beat sync, alternates/shot swap, timeline editor,
zoom/pan transforms, WebCodecs engine, quota/billing, resumable background jobs.

## Phases
1. Compositor + code-graphics renderer (desktop + server for web) + kinetic captions +
   transitions + SFX/music ducking.
2. Full-screen b-roll inserts + b-roll understanding + stock search + per-shot storyboard.
3. AI-written infographics and motion graphics + template library + brand kit.
4. Person segmentation + composite layouts (cut-out over b-roll, phone mockup, framed result).
5. Concept options + storyboard review page with per-shot notes and AI revision.
6. Polish: more templates, emotion-driven effects tuning, performance.

## Known risks / open questions
- **We removed a similar layer before**: AI-generated Remotion components + overlays were
  removed on 2026-08-12 (code parked in `desktop/_removed/`). Before Phase 1, find out why
  (speed? breakage? no web rendering?) and design around it.
- Rendering heavy graphics in a phone browser may be slow → server-side render option.
- AI editing taste needs several live iterations per prompt change (see the cut-prompt eval
  method memory): judge on ≥3 runs with contact sheets.
- Not planned: colour grading, 3D, multi-cam sync; object tracking and non-person cut-outs are
  later possibilities.
